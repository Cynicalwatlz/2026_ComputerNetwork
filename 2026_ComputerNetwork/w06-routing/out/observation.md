Task 1
동일 비용의 최단 경로는 첫 경유 라우터의 이름순으로 선택했으며, 실제 OSPF는 동일 비용 다중 경로를 사용할 수 있다.
u에서 w까지 직접 연결 비용은 5지만 x와 y를 경유하면 3이므로 다음 홉은 x이다.
u-x 연결 장애 후 w, x, y, z의 다음 홉은 v로 변경되고, v의 다음 홉은 유지되었다.

Task 2
국내 경로의 캠퍼스 이탈 지점과 해외 경로의 해저 케이블는 확인하지 못했으며, Anycast는 13홉에 도달했다.
'* * *'는 응답 제한이나 패킷 차단으로 발생했다.
세 라우터 모두 원격 경로를 학습했으며, 장애와 복구 시 경로 변경 감지는 각각 1초였다. Hello/Dead 간격은 10초/40초이나 직접 링크를 조작했으며, 장애 탐지와 이웃 재형성 과정은 다르다.
비용 변경 후 경로 전환은 2초였으며, 일반적인 장애는 탐지 시간이 필요한 반면 비용 변경은 LSA 전파로 처리되므로 더 빠를 수 있다.

Task 3
최단 거리와 경로 정보를 추가 메모리에 저장해 링크 변경의 영향을 판단하고, 불필요한 전체 SPF 재계산을 생략했다.
사용하지 않는 링크의 장애·비용 증가와 최단 경로를 개선하지 않는 변경은 재계산을 생략하고, 필요한 경우만 수행하여 SPF 실행을 1,001회에서 212회로 79% 줄였다.
추가 검사로 Python 실행 시간은 0.63초에서 0.87초로 증가했으나, 실제 라우터에서는 전체 SPF 재계산에 따른 CPU 부담을 줄여준다.
